Claude Code に「消費税法30条を見せて」と頼むと、もっともらしい条文が返ってきます。ただ、その条文が今の版かどうかは分かりません。条番号や文言を取り違えていても、読み手はなかなか気づけません。

この記事では、条文を**公式の e-Gov 法令API から毎回取得し、取れなかったら記憶で補わない**スキル `houki-lookup` を紹介します。MIT ライセンスで公開しています。

https://github.com/ayukari/jp-backoffice-skills

## モデルの記憶にある条文の弱点

法令について、モデルの記憶には2つの弱点があります。

- **古い**：学習した時点より後の改正を知りません。消費税法のように改正の多い法令では、特に問題になります。
- **正確でない**：「第57条の4」を「第57条の2」と取り違えても、見た目では区別がつきません。

そこで、役割を次のように分けました。

| スクリプト（law_lookup.py） | Claude |
|---|---|
| e-Gov 法令API から条文を取得し、原文のまま出す | 条文を読んで説明する |
| 法令名・法令番号・施行日・URL を「出典」として付ける | 回答の最後に出典を書く |
| 取得に失敗したら終了コード 1 で止まる | 失敗したことをそのまま伝える |

## 実際の出力

以下は、e-Gov 法令API の実際の応答を記録したファイル（テスト用）を使って、スクリプトを動かした出力です。

法令名だけを渡すと、候補の一覧を返します。

```
$ python3 law_lookup.py --title 消費税法
消費税法（昭和六十三年法律第百八号）施行日 2026-10-01 https://laws.e-gov.go.jp/law/363AC0000000108
消費税法施行令（昭和六十三年政令第三百六十号）施行日 2026-10-01 https://laws.e-gov.go.jp/law/363CO0000000360
```

条番号も渡すと、条文と出典を返します（途中を省略しています）。

```
$ python3 law_lookup.py --title 消費税法 --article 第三十条
第三十条（仕入れに係る消費税額の控除）
事業者（第九条第一項本文の規定により消費税を納める義務が免除される事業者を除く。）が、国内において行う課税仕入れ（…）
　一　国内において課税仕入れを行つた場合　当該課税仕入れを行つた日
　二　国内において特定課税仕入れを行つた場合　当該特定課税仕入れを行つた日
…
13　第七項に規定する帳簿の記載事項の特例、当該帳簿及び同項に規定する請求書等の保存に関する事項その他前各項の規定の適用に関し必要な事項は、政令で定める。

出典: 消費税法（昭和六十三年法律第百八号）施行日 2026-10-01 https://laws.e-gov.go.jp/law/363AC0000000108
```

ポイントは3つです。

- 「消費税法」で検索すると施行令も返ってきますが、**法令名が完全に一致するもの**を選びます。施行令の30条を取ってしまうことはありません。
- 条番号は `30`・`第30条`・`57の4`・`第五十七条の四` のどれで書いても同じように扱います。
- 出典に**施行日**を付けます。どの時点の条文かが分かるようにするためです。

## 取れなかったときに「記憶で補わない」

このスキルでいちばん大事なのは、成功したときではなく、失敗したときの動きです。

```
$ python3 law_lookup.py --title 消費税法 --article 30
e-Gov 法令API に接続できませんでした: network down（記憶で条文を補わないこと）
$ echo $?
1
```

（接続できない状態をテスト用のクライアントで再現した出力です。実際のエラー文は原因によって変わります。）

接続できなかったときは、エラーメッセージに「記憶で条文を補わないこと」と書き、終了コード 1 で止まります。SKILL.md にも同じルールを書いています。

```markdown
- スクリプトが終了コード 1 で失敗したら（見つからない・接続できない）、**記憶で条文を補わず**、
  取得できなかったことをそのまま伝える。ユーザーには e-Gov 法令検索（https://laws.e-gov.go.jp/）で
  確認するよう案内する。
```

このルールがないと、API に接続できなかったときに Claude が自分の知識で条文を「再現」してしまいます。再現された条文は本物と見分けがつかないので、エラーメッセージと SKILL.md の両方に書いておくのが安全です。

## テストは記録した応答で行う

公開 API に毎回アクセスするテストは遅く、相手のサーバーにも負担をかけます。そこで、実際の応答を一度だけ保存し、テストではそのファイルを返す偽のクライアントを使っています。

```python
# test_law_lookup.py より抜粋
class FakeClient:
    """Serves recorded e-Gov responses, so tests never hit the public API."""
    def search_laws(self, **kw):
        return json.loads((FIX / "laws_shohizei.json").read_text(encoding="utf-8"))

    def get_article(self, law_id, article):
        return json.loads((FIX / "law_data_shohizei_art30.json").read_text(encoding="utf-8"))
```

接続できない場合のテストも、この偽のクライアントに例外を投げさせて確かめています。上の「実際の出力」も、このクライアントで動かしたものです。

## 社内ネットワークでは接続できないことがある

会社のネットワークやクラウドの実行環境では、外部への接続が許可制になっていることがあります。`laws.e-gov.go.jp` に接続できない環境では、このスキルは条文を取れません。その場合も、上のとおり記憶で補わずに止まります。使う前に、接続できるかを確かめてください。

```bash
claude plugin marketplace add ayukari/jp-backoffice-skills

```
