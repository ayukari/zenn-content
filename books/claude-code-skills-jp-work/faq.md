スキル集 jp-backoffice-skills を使い始めるときによく出る疑問をまとめました。

## インストール・更新

### Python は必要ですか？

はい。計算や点検のスクリプトは Python 3 で書かれています。標準ライブラリだけで動くので、`pip install` で追加のパッケージを入れる必要はありません。ターミナルで `python3 --version` が動けば準備はできています。

### スキルが呼ばれていないようです

まず、プラグインが有効になっているかを確認します。

```bash
claude plugin list
```

`jp-backoffice-skills@jp-backoffice` が `enabled` になっていれば、インストールは完了しています。それでも呼ばれない場合は、依頼文でスキル名を指定してください（例：「invoice-jp スキルで請求書を作って」）。

### 最新版に更新するには？

マーケットプレイスの情報を更新してから、プラグインを更新します。更新後は Claude Code の再起動が必要です。

```bash
claude plugin marketplace update jp-backoffice
claude plugin update jp-backoffice-skills@jp-backoffice
```

## 使うとき

### スクリプトの実行許可を聞かれます

スキルは計算や点検のために `python3` でスクリプトを実行します。Claude Code はコマンドを実行する前に許可を求めるので、内容を確認して許可してください。スクリプトはすべて GitHub で公開しているので、中身を読んでから使うこともできます。

### 請求書の登録番号が本物かどうかも確かめられますか？

いいえ。点検スクリプトが確かめるのは、「T＋13桁」という形式で書かれているかどうかだけです。その番号が実際に登録されているかは、国税庁の「適格請求書発行事業者公表サイト」で確認してください。公表サイトの Web-API とつなぐ方法は、9章で触れています。

### 法令検索（houki-lookup）が「接続できませんでした」で止まります

`laws.e-gov.go.jp` に接続できない環境では、条文を取得できません。会社のネットワークやクラウドの実行環境では、外部への接続が許可制になっていることがあります。その場合、スキルは記憶で条文を補わずに止まります。これは誤った条文を出さないための意図した動きです。

### 出てきた請求書や稟議書は、そのまま使ってよいですか？

数字の計算はスクリプトで行っているので、税率ごとの端数処理などは規則どおりです。ただし、取引の内容や金額が正しいか、制度の経過措置に当たるかといった判断は、使う人が確認してください。税務・法務の個別の判断は、税理士などの専門家や国税庁の公式情報で確認することをおすすめします。

## カスタマイズ

### 自分の会社のルールを足せますか？

できます。たとえば敬語チェックのルールは `keigo_rules.json` に並んでいるので、社内でよく見る誤りを1行足すだけで、チェックの対象になります。スキルの手順そのものを変えたい場合は、SKILL.md を書き換えます。作り方は4章以降で説明しています。

### 不具合を見つけたら？

GitHub の Issue で知らせてください。依頼文と、期待した結果・実際の結果を書いてもらえると、直しやすくなります。
