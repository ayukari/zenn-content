この章では、公開スキル集 jp-backoffice-skills をインストールし、インボイス制度に対応した請求書を作ります。既存の請求書の点検までやってみます。

## インストール

Claude Code のプラグインとして配布しています。ターミナルで次の2つのコマンドを実行します。

```bash
claude plugin marketplace add ayukari/jp-backoffice-skills
claude plugin install jp-backoffice-skills@jp-backoffice
```

1行目でスキル集の配布元（marketplace）を登録し、2行目でプラグインをインストールします。`claude plugin list` を実行して、`jp-backoffice-skills@jp-backoffice` が `enabled` と表示されればインストールは完了です。

入っているスキルは次の8つです（v0.2.0 時点）。

| スキル | できること |
|---|---|
| `invoice-jp` | インボイス対応の請求書の作成と点検（源泉徴収・立替金にも対応） |
| `keigo-email` | ビジネスメールの作成と敬語の添削 |
| `ringi-jp` | 稟議書の作成と添削 |
| `nippo-jp` | 日報・週報の作成 |
| `jp-tech-writing` | 技術文書の校正 |
| `expense-ledger-jp` | 経費帳の作成 |
| `gijiroku-jp` | 議事録の作成と点検（決定事項・ToDo） |
| `houki-lookup` | 法令の条文検索（e-Gov 法令API） |

## 請求書を頼んでみる

Claude Code を起動して、ふつうに頼みます。スキル名を指定する必要はありません。

```
山田デザイン（登録番号T1234567890123）から株式会社サンプルへの請求書を作って。
10/4発行、10/1納品。Webデザイン一式10万円（税抜）と、
打ち合わせ用の菓子500円×2（軽減税率）。支払期限10/31。
```

Claude は `invoice-jp` スキルを読み込み、スキルの手順どおりに進めます。

1. 請求書に必要な情報がそろっているかを確認する（足りなければまとめて質問する）
2. 金額と消費税を**スクリプトで**計算する
3. 同じデータから請求書を出力する

出力された請求書は次のとおりです（実際の出力をそのまま載せています）。

```markdown
# 請求書

請求日: 2026年10月4日
取引年月日: 2026年10月1日

株式会社サンプル 御中

発行者: 山田デザイン（登録番号: T1234567890123）

**ご請求金額（税込）: 111,080円**

| 品目 | 数量 | 単価（税抜） | 金額（税抜） | 税率 |
|---|---:|---:|---:|---:|
| Webデザイン一式 | 1 | 100,000 | 100,000 | 10% |
| 打ち合わせ用の菓子 ※ | 2 | 500 | 1,000 | 8% |

| 税率 | 対象額（税抜） | 消費税額 | 合計（税込） |
|---|---:|---:|---:|
| 8%対象（軽減税率） | 1,000 | 80 | 1,080 |
| 10%対象 | 100,000 | 10,000 | 110,000 |

※は軽減税率（8%）対象品目です。

お支払期限: 2026年10月31日
```

`--html` を付けると印刷用の HTML でも出力できます。ブラウザで開いて PDF として保存すれば、そのまま送付できます。

## なぜスクリプトで計算するのか

適格請求書（インボイス）には、次の6項目の記載が必要です。

1. 発行者の氏名または名称と、登録番号
2. 取引年月日
3. 取引内容（軽減税率の対象品目である旨を含む）
4. 税率ごとに区分した対価の合計額と、適用税率
5. 税率ごとに区分した消費税額等
6. 書類の交付を受ける事業者の氏名または名称

特に注意したいのは5番目です。消費税の端数処理は、**1つの請求書につき、税率ごとに1回**と定められています。明細の1行ごとに端数を処理して合計すると、金額がずれることがあります。

LLM はこうした細かい計算規則を、文脈によって守ったり守らなかったりします。そこでこのスキルでは、計算を `invoice_calc.py` というスクリプトに任せ、Claude にはその結果を使わせています。計算規則はテストで固定しているので、何度頼んでも同じ結果になります。この設計の考え方は5章で詳しく説明します。

## 情報が足りないとき

次のように、情報が足りない頼み方をした場合はどうなるでしょうか。

```
取引先に請求書を出したい。デザイン料5万円です。
```

スキルには「推測で埋めずに、足りない情報をまとめて質問する」と書いてあります。そのため Claude は、発行者名・登録番号・宛名・取引日・金額が税込か税抜かといった不足項目をまとめて質問します。登録番号がない場合は、免税事業者は適格請求書を発行できない点にも触れます。

## 既存の請求書を点検する

受け取った請求書や、自分で作った請求書がインボイス制度の要件を満たしているかも確認できます。

```
この請求書、インボイス制度的に大丈夫？

請求書
株式会社テスト 御中
2026年10月4日
山田商店
品目 作業A 3 333 999 10%
| 10%対象 | 999 | 98 |
```

Claude は `check_invoice.py` で6項目を機械的に確認します。このケースでは、次の3点を指摘しました（実際の判定結果の要約です）。

| 項目 | 判定 | 内容 |
|---|---|---|
| 登録番号 | 不足 | T+13桁の登録番号がない |
| 取引年月日 | 要確認 | 請求日はあるが、取引日の記載がない |
| 税率ごとの消費税額 | 要確認 | 999円の10%は99円（切り捨て）か100円（四捨五入・切り上げ）になるはずが、98円になっている |

この例では、明細ごとに端数処理した場合も 333円×3行で99円になるため、98円はどの端数処理でも説明できません。Claude は計算誤りの可能性を伝え、直し方を示します。スクリプトは文字列を機械的に確認するだけなので、発行者名などは最後に目で確認してください。

:::message
インボイス制度の経過措置や特例など、判断が必要なケースではスキルは断定しません。個別の判断は、税理士や国税庁の公式情報で確認してください。
:::
